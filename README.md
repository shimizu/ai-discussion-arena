# 円卓 — AI討議アリーナ

Claude・GPT・Gemini に **議長 / 肯定側 / 否定側** の役をランダムに割り当て、
与えられたテーマについて討議させるブラウザアプリです。
三者は必要に応じて **e-Stat（政府統計）** と **World Bank（世界開発指標）** から
実データを取りに行き、それを根拠として論を組み立てます。

サーバーは不要です。APIキーと討議の記録はブラウザの localStorage にのみ保存され、
各社のAPI以外へは送信されません。

保守・拡張を担当する技術者は、[技術引き継ぎガイド](docs/README.md) を参照してください。複数AI APIの統合方式は [専用ドキュメント](docs/ai-api-orchestration.md) に分けて説明しています。

---

## 使い方

```bash
npm install
npm run dev      # http://localhost:3100
```

1. 右上の **API設定** から使いたいAIのキーを登録します。
2. 各プロバイダの **一覧を取得** を押すと、そのキーで使えるモデルが選べます（キーの疎通確認も兼ねます）。
3. e-Stat のアプリケーションIDを入れると、日本の政府統計も討議で参照されるようになります。
4. テーマを入力して **討議を始める**（⌘/Ctrl + Enter でも可）。

キーを登録したAIだけが参加します。3社そろえば三役が別々のAIになり、
2社以下なら1つのAIが複数の役を兼任します（1社だけでも討議は成立します）。

### 進行

```
開会（議長）
 └ 第1巡  肯定側 → 否定側
   第2巡  否定側 → 肯定側      ← 巡ごとに先手を入れ替える
        ＋ 議長の中間整理       ← 既定で2巡ごと
   第3巡  肯定側 → 否定側
   …
   第6巡まで
総括（議長）
```

- **巡回数の上限**（既定6）を超えると、議長が総括に入ります。
- **議長が整理に入る間隔** を 0 にすると中間整理は挟まれません。
- 議長が中間整理で「論点は出尽くした」と判断した場合、残りの巡を飛ばして総括へ移ります。
- **合意に至る必要はありません。** 総括では、合意点・対立点・未解決の論点を分けて記録し、
  何が判断を分けたのかを書くよう指示しています。議長は勝敗を判定しません。

### 記録の保存

討議の発言と取得データはブラウザに自動保存され、次に開いたときそのまま復元されます。
討議の途中でページを閉じた場合も、そこまでの記録は残ります（中断された旨が表示されます）。

**新しいテーマで討議を始めると、前の記録は破棄されてから討議が始まります。**
残しておきたい討議は、始める前に出力してください。

| ボタン | 出力 |
|---|---|
| 議事録を出力 | Markdown。参加者・全発言・参照した資料・失敗した順番・提出資料の原文 |
| データを出力 | CSV。資料ごとにメタデータ行（出典・ツール・引数・提出者・行数）＋表を連結した1ファイル |

CSV はBOM付きUTF-8なので、日本語版Excelでもそのまま開けます。
数値はロケール整形せずに書き出すため、表計算ソフト側で数値として扱えます。
資料番号は議事録とCSVで一致するので、発言中の数値を原データまで辿れます。

討議中に取得した全行がCSVに入りますが、ブラウザに保存されるのは1資料あたり500行までです。
リロードを挟まなければ全行が出力できるので、大きなデータを取った回は先に出力してください。

### 設計上の判断

**共有議事録方式** — 各AIには自分の内部履歴ではなく、全員分の発言を整形した
共有議事録テキストを渡します。3社のメッセージ形式の違いが討議そのものへ漏れず、
役割やモデルを差し替えても議事録の連続性が保たれます。
ツールの往復は1ターン内で完結させ、ベンダー固有のツール履歴を外へ出しません。

**資料の共有** — 誰かが取得したデータは「提出資料」として蓄積され、
以降の発言者のプロンプトに含まれます。同じ統計を3人が別々に取りに行くことを防ぎ、
発言中の数値を原データまで辿れるようにしています。

**先手の入れ替え** — 巡ごとに肯定側と否定側の順番を入れ替えます。
「常に後から反論できる」側の有利さを消すためです。

**部分的な失敗を許容** — 1人のAIが認証エラー等で落ちても討議は続行します。
ツールの失敗はエラー内容をモデルへ返し、条件を直すか方針を変えるかを判断させます。

**読ませる表と書き出す表を分ける** — ツールは `content`（AIに読ませる文字列）と
`dataset`（CSV用の生データ）の両方を返します。前者は表示40行までで数値も読みやすく
整形しますが、後者は取得した全行を生の数値のまま保ちます。
1つの文字列を両方の用途に使い回すと、AIに読ませるために切った行がCSVからも消え、
読みやすさのために入れた桁区切りが表計算ソフトで文字列として解釈されてしまいます。

### ベンダー差で特に注意した点

| | 対応 |
|---|---|
| Anthropic | ブラウザ直叩きには `anthropic-dangerous-direct-browser-access: true` が必須 |
| OpenAI | **Responses API (`/v1/responses`) を使う。** GPT-5.x 系は Chat Completions で「関数ツール + 推論」の組み合わせを受け付けず、`reasoning_effort` を `none` にしろというエラーを返す。討議で推論を切りたくないため Responses へ寄せた。`temperature` / `max_tokens` / `reasoning_effort` は送らない。ツール定義は平坦な形（`function` でネストしない）で `strict: false`、結果は `function_call_output`。前ターンの `output` 配列を丸ごと戻して推論の文脈を保つ |
| Gemini | model ターンの `parts` を**そのまま履歴へ戻す**。Gemini 3系は functionCall に思考署名を載せており、再構成すると関数呼び出しの続きが成立しない。スキーマも OpenAPI サブセットへ変換（`additionalProperties`・`minimum` 等を除去し型名を大文字化）しないと 400 になる |

## 利用できるツール

| ツール | 出典 | 用途 |
|---|---|---|
| `estat_search_tables` | e-Stat | 統計表をキーワード検索し statsDataId を特定 |
| `estat_get_metadata` | e-Stat | 分類事項とコード一覧を確認（コードの推測を防ぐ） |
| `estat_fetch_data` | e-Stat | 確認済みコードで統計数値を取得 |
| `worldbank_search_indicators` | World Bank | WDI の指標を英語キーワードで検索 |
| `worldbank_fetch_indicator` | World Bank | 国×指標の時系列を取得 |

e-Stat のアプリケーションIDが未設定のときは、e-Stat 系ツールは
そもそもAIへ提示されません（使えないツールを見せない）。

World Bank の指標カタログ（約1500件）は初回検索時に取得してセッション中キャッシュします。
初回だけ数秒かかります。v2 API に全文検索が無いため、カタログを取得して
クライアント側で照合する方式です。

## セキュリティ

本番ビルド時、`index.html` に CSP の meta を注入します。

```
connect-src 'self'
  https://api.anthropic.com
  https://api.openai.com
  https://generativelanguage.googleapis.com
  https://api.e-stat.go.jp
  https://api.worldbank.org
```

APIキーがこの5つ以外のホストへ送られる経路を塞ぐためのものです。

localStorage にはAPIキーのほか、**討議の発言と取得データも保存されます。**
共有端末で使った場合は、API設定の「保存したキーと討議記録をすべて削除」を実行してください。

## テスト

```bash
npm test
```

`fetch` をスタブして、各社へ実際に送られるリクエストボディを検証しています
（ツール往復の形式、思考署名の保持、スキーマ変換、e-Stat のフィルタ展開など）。
討議ループは偽プロバイダを注入して、進行順・早期終了・中断・部分失敗を確認しています。
保存まわりは localStorage をスタブして、往復・行数の切り詰め・容量超過時の劣化・
壊れたデータの除去を見ています。書き出しは CSV のクォートと資料番号の対応を検証しています。

## 未検証の項目

開発環境から外部APIへ到達できなかったため、実キーでの疎通は未確認です。
最初に動かすときは次を確認してください。

- **OpenAI のモデルID** — 既定値を `gpt-5.6-terra` としています。
  API設定の「一覧を取得」で実際に使えるIDへ差し替えてください。
  Claude は `claude-opus-4-6`、Gemini は `gemini-3.6-flash` を既定にしています。
- **暗号化推論の持ち回り** — `store: false` で会話をOpenAI側に保存させず、
  推論アイテムを暗号化して受け取り次のリクエストへ戻しています。
  対応していないモデルでは自動的にこの機能を外して再送します（推論の文脈は失われますが討議は継続します）。
  この降格はモデルごとに記録されるので、設定でモデルを変えれば再挑戦します。
- **World Bank の CORS** — `api.worldbank.org` はブラウザからの直接アクセスを許可しているはずですが、
  実測はしていません。もし遮断される場合は簡易プロキシが必要になります。
- **コスト** — 10巡の討議は 20〜25 回のモデル呼び出しになります。
  まず巡回数を 2〜3 に下げて動作を確認することをおすすめします。
